# K3 gates: the admin API and Studio's Knowledge tab

Measured 2026-10-04 with `scripts/bench_k3.py` (raw results: `k3.json`; screenshots: `k3/`),
operonx main (`2279cea`), operonx-studio `feat/knowledge-tab`, headless Chromium (playwright
1.63). Answer model `gpt-4o-mini` (Operon's `resources.yaml`; no key printed), embedder
`intfloat/multilingual-e5-small`, the lexical index `vi` + folding, hybrid search, k = 8.

## Setup

- **Corpus**: 20 legal PDFs and 12 Wikipedia articles drawn with seed 3 from the D5 corpus
  (`d5.md`; licenses there), 32 documents, 688 chunks, ingested in 192.5 s on CPU.
- **Project**: an operonx project whose `kb_admin` asgi service is
  `kb_admin_app(llm="gpt-4o-mini")`, served with `operonx serve --only kb_admin`, traced to the
  project's local runs. Studio runs on another port with the project open; nothing is mocked
  between the browser and the model.
- **Questions**: 40 written by the answer model, each from one random chunk of a PDF (seed 3,
  chunks of ≥ 40 tokens; `QUESTION_PROMPT`). The questions are not labels: the gate checks
  where a citation leads, not whether the answer is right.

## Gate (b): a cited answer opens the correct page and box — **20 / 20**

The script asks the questions in order in the Ask page and takes **every** verified citation of
every answer until it has 20 (15 questions asked; 20 citations verified and shown, 4 dropped by
the verifier and never shown). For each it clicks the answer's `[n]` (or, for a second
citation behind the same marker, its row in the citation list) and checks the viewer:

| check | how | passed |
|---|---|---|
| the page shown is the cited page | `.kbpage[data-page]` = the page of the citation's first box | 20 / 20 |
| the image is that page | the `<img>` loaded (`naturalWidth > 0`) from `/versions/{cited version}/pages/{page}/image` | 20 / 20 |
| the lit boxes are the citation's boxes | the `.kbcite` overlays' left/top/width/height equal the citation's boxes on that page (±0.01 %) | 20 / 20 |
| the quote is inside those boxes | **independent of the KB**: pdfium's own text layer (`get_text_bounded`) inside each cited box, on the PDF file itself, contains the quote (NFC; whitespace and hyphens ignored) | 20 / 20 |

paragraph's first line, indented, is its own region).

**The check discriminates.** Control: the same pdfium test run on the *wrong* boxes (the
nearest other body element on the cited page) rejects 17 / 17 (the other 3 cited pages hold a
single element, a table, so there is no wrong box on them).

**What it does not cover.** No sampled citation pointed into a source without pages (the
questions come from PDFs): the text view's lighting of a quoted span is covered by the
`textBands` tests (`tests/js/kbview.test.mjs`) and the screenshots `*-text.png`, not by this
gate. A box is an element's region (a paragraph, a list item, a table), not the quote's own
glyphs: the quote lies inside it, which is what "opens the correct box" means here.

## Gate (a): screenshots

Every view at desktop (1440 x 900, Studio's side panel open as it opens by default, and once
closed) and phone (390 x 844) width, light and dark — `k3/{desktop,phone}-{light,dark}-*.png`
and `k3/desktop-nopanel-light-*.png`:

| view | what it shows |
|---|---|
| `documents` | collections with counts and modes; the spec in a line; the documents table (search, status, pages) |
| `viewer` | a PDF page with element boxes coloured by kind family and chunk outlines; the chunk list |
| `chunk` | the chunk inspector: text, what was embedded (template, heading context highlighted), index keys, pages, neighbours |
| `text` | a source without pages: its canonical text in chunk bands |
| `ask` | the query form (modes, answer, rerank, k, filter) and the answer with `[n]` markers |
| `ask-hits` | one list per mode side by side, each with its trace link |
| `citation` | the cited page opened from `[n]`, the cited boxes lit |
| `gate-first-citation` | the first citation of the gate run |

Each was looked at; the layout fixes they led to are in the Studio PR (the viewer takes the
collections' column, the inspector stacks under the page when the pane is narrow, the
documents table and the hit lists reflow by the pane's width, not the window's).
