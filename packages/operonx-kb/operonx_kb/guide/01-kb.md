# Knowledge base: operonx-kb

```bash
uv add operonx-kb                    # extras: pdf, faiss, ocr, s3, drive, mcp, admin
```

It is imported as `operonx_kb` (or `operonx.kb`, the same modules).

## Resources

Everything the knowledge base touches is a `resources.yaml` key: the
catalog (documents, versions, chunks), the blob store (the original
files), the lexical index, the embedder and the vector store.

```yaml file=resources.yaml
kb_catalog:main:
  path: kb/catalog.db                # SQLite; Postgres in production
kb_blob:main:
  root: kb/blobs
kb_lexical:main:
  path: kb/lexical.db                # SQLite FTS5
vector_store:kb:
  api_type: faiss                    # extra `faiss`; or pgvector, qdrant, …
  metric: cosine
  dim: 32
fake_embedding:hash:                 # offline stand-in for these examples;
  dim: 32                            # in production an `embedding:` model
```

```markdown file=handbook.md
# Leave policy

Every employee gets 14 days of paid leave a year. Unused days carry over to March.

# Expenses

Taxis after 10 pm are paid by the company. Keep the receipt.
```

## A collection, add, search

```python
import asyncio

import operonx
import operonx_kb.testing.fakes  # noqa: F401 — registers fake_embedding: (examples only)
from operonx_kb import CollectionSpec, DenseIndexSpec, KnowledgeBase
from operonx_kb.model.collection import LexicalIndexSpec

operonx.bootstrap(resources="resources.yaml")


async def main():
    kb = KnowledgeBase()  # kb_catalog:main, kb_blob:main
    kb.create_collection(
        "handbook",
        CollectionSpec(
            dense=DenseIndexSpec(embedder="fake_embedding:hash", store="vector_store:kb"),
            lexical=LexicalIndexSpec(),
            filterable={"dept": "keyword"},
        ),
    )
    about = {"tags": ["hr"], "acl": ["team:hr"], "metadata": {"dept": "hr"}}
    added = await kb.add("handbook", "handbook.md", key="handbook.md", **about)
    assert added["action"] == "new"
    again = await kb.add("handbook", "handbook.md", key="handbook.md", **about)
    assert again["action"] == "skip"  # same bytes: nothing parsed or indexed

    found = await kb.search("handbook", "paid leave days", mode="lexical", k=3,
                            filter={"acl_any": ["team:hr"], "fields": {"dept": "hr"}})
    top = found["hits"][0]
    assert "14 days of paid leave" in top["text"]
    assert top["key"] == "handbook.md" and top["heading_path"]  # where it came from


asyncio.run(main())
```

- `add` takes a path or `data=` bytes; `key` is the document's identity, so
  adding the same key again makes a new version only when the bytes
  changed. Its `tags`, `acl` and `metadata` **replace** the document's
  every time — re-adding without `acl` removes the ACL.
- `mode`: `dense`, `lexical`, `hybrid` (both, fused), `tree`, `graph`.
  `reranker="ce"` reranks with a `reranking:` resource.
- `filter`: `tags_any`, `tags_all`, `acl_any`, `document_ids`, and
  `fields` on the names in `filterable`. A field the collection did not
  declare raises.
- `kb.ask(collection, question, "assistant")` answers with an `llm:`
  resource; every citation's quote was found in its source and carries
  its span, pages and boxes, and the rest are in `answer["dropped"]`.

## Ingest a folder: a Job

`ingest_flow` is a graph behind doors, so a `Job` runs it once per file —
recorded, resumable by key, and an unchanged file is skipped:

```python
import operonx
import operonx_kb.testing.fakes  # noqa: F401
from operonx.app.jobs import Job
from operonx_kb import CollectionSpec, DenseIndexSpec, KnowledgeBase
from operonx_kb.graphs import ingest_flow
from pathlib import Path

operonx.bootstrap(resources="resources.yaml")
KnowledgeBase().create_collection(
    "docs", CollectionSpec(dense=DenseIndexSpec(embedder="fake_embedding:hash",
                                                store="vector_store:kb"))
)

ingest = Job(
    "ingest_docs",
    graph=ingest_flow,
    items=lambda: sorted(Path(".").glob("*.md")),  # a path per item; S3Source / DriveSource too
    key=lambda path: path.name,
    inputs={"collection": "docs", "catalog": "kb_catalog:main", "blobs": "kb_blob:main"},
)
run = ingest.run_sync()
assert run.status == "ok"
assert [r["action"] for r in run.results.values()] == ["new"]
```

Files in S3 or Google Drive (extras `s3`, `drive`): `items=S3Source("bucket",
prefix="hr/")` or `items=DriveSource(folder_id)`, from `operonx_kb.sources`.

## Search as a step of your graph

A search is an operonx graph, so it is one step of your own flow, traced
with it:

```python
import asyncio

import operonx
import operonx_kb.testing.fakes  # noqa: F401
from operonx import END, START, Operon, graph, op
from operonx_kb import CollectionSpec, DenseIndexSpec, KnowledgeBase
from operonx_kb.graphs import search
from operonx_kb.model.collection import LexicalIndexSpec

operonx.bootstrap(resources="resources.yaml")


@op(bound="sync")
def cite(hits: list = None) -> dict:
    top = hits[0]
    return {"reply": f"{top['text']} ({top['key']})"}


@graph
def answer_flow(question, catalog):
    found = search(query=question, collection="faq", filter=None, k=3, mode="lexical",
                   catalog=catalog)
    reply = cite(hits=found["hits"])
    START >> found >> reply >> END


async def main():
    kb = KnowledgeBase()
    kb.create_collection("faq", CollectionSpec(
        dense=DenseIndexSpec(embedder="fake_embedding:hash", store="vector_store:kb"),
        lexical=LexicalIndexSpec()))
    await kb.add("faq", "handbook.md", key="handbook.md")
    engine = Operon(answer_flow, params={"question": None, "catalog": None})
    out = await engine.run(inputs={"question": "taxi receipt", "catalog": "kb_catalog:main"})
    assert "$errors" not in out and out["reply"].endswith("(handbook.md)")


asyncio.run(main())
```

`search` reads the collection's settings per run, so it is defined once at
module level and the collection is an input.

## Tools for an agent, and MCP

With operonx-agents installed, `kb_tools` is a read-only `kb_search` /
`kb_read` toolset. The scope comes from your code or the run's context —
the model only sends a query — and `kb_read` checks it again:

```python norun
from operonx.agents import Agent, Model
from operonx.kb.tools import kb_tools

tools = kb_tools(kb, "handbook", scope=lambda ctx: {"acl_any": ctx.deps.principals})
agent = Agent(name="hr", model=Model("assistant"), tools=[tools])
```

A client outside your code (Claude Desktop, an IDE) gets the same two tools
over MCP (extra `mcp`). The scope is the server's, fixed when it starts —
one server per audience:

```bash
operonx-kb mcp handbook --acl team:hr
```

## The command line

```bash
operonx-kb query handbook "how many days of leave" --mode hybrid --tag hr
operonx-kb query handbook "how many days of leave" --answer assistant
operonx-kb eval handbook datasets/handbook.jsonl --mode hybrid
```

Scanned PDFs: `CollectionSpec(ocr=OcrSpec(languages="vie+eng"))` (extra
`ocr`, plus the `tesseract` binary) reads a page with no text layer.
